# 当前活动状态（0.9.0）

NPC 的当前活动由现有游戏日程、动画、控制器和已验证的 AIWorld 行动共同确定。`NpcJobState` 是有限状态快照：每次读取重新从游戏事实推导，不额外保存一份“真实日程”，不让模型写这个字段，也不新增巡逻、工作需求或自主任务队列。

## 状态来源与变化

| 证据 | 当前活动 |
| --- | --- |
| NPC 是当前剧情的参与者 | Event：参与剧情，优先级最高 |
| 跟随执行器实际持有该 NPC | Following：陪同玩家；路线失败/控制器被替换则 Blocked/Interrupted |
| 已接受出行、实际路线仍由 AIWorld 持有 | Travelling 或等待路径推进；读到目标地点和格子 |
| 到达执行器目标格，且没有继续行走 | Arrived；不宣称到达即自动开始某项工作 |
| 约会管理器已确认到达，当前位置仍符合且没有移动 | Waiting：等待约定会面 |
| 返回规划器仍持有这一次恢复执行 | Returning：恢复原有安排 |
| 实际保留路线属于当天选中的日程 | Travelling：去当天日程的真实目的地 |
| 日程目标地图与格子一致，没有未完成路径或移动 | Arrived |
| 上述到达条件成立，且日程结束动作与正在执行的动画标识一致 | Doing：读书、洗碗、睡觉、葡萄园劳作等已知活动 |
| 被其他控制器接管或关闭当天日程 | Interrupted；原计划保留，但不称正在执行 |
| 缺失或无法确认证据 | Unknown；不靠时钟或模型猜活动 |

仅接受一个明天的约会时，当前工作不会立刻改成“去赴约”。`CurrentGoal` 保留未来安排，`Job` 负责当前活动。现有 `CurrentActivity` 粗分类继续兼容旧逻辑；模型回答“正在干什么”以新的 `CURRENT JOB` 为准。

代码读取状态不调用 `IsArrived`、寻路或移动 Tick，不会因为打开 F9 而推进路线、传送或执行动作。状态本身不增加模型请求。

## 潘妮读书与上课

读取本机 SVE 的 `code/NPCs/Penny.json`，其 `Tue` 和 `marriageJob` 路线使用 `ArchaeologyHouse 17 9 ... penny_read`。这和独自在镇上读书共用动画，不能仅凭 `penny_read` 宣称“正在上课”。

内置 `Penny.LibraryLesson` 规则要求：潘妮实际在该教室格、正在执行匹配的日程读书动作，贾斯/文森特/雷欧至少一人真实在同地图五格内停留，且没有移动、临时控制器或剧情接管。符合才把活动注释细化为“给在场的孩子上课、带他们读书”；否则保持实际读书或未知状态。不猜授课科目、教学进度或已经完成课程。

这是有明确前提的语义注释，证据标记为 `schedule-animation-and-context-rule`，不是游戏本身提供了“教学工作”字段。具体星期和时刻仍由原版/SVE 当前加载的日程决定；没有硬编码“09:30 必在路上、13:00 必在教课”。

## 对话如何改变活动

玩家请求 → 已有解析、NPC 同意、权限/路径校验 → 现有跟随/出行/约会执行器真正启动 → 下一次状态读取反映新活动 → 新对话得到新状态。

取消、到达、失败、剧情接管或恢复日程同样反馈。模型仅说“我现在去工作了”不会改状态、瞬移、生成工作或覆盖日程。此次没有新增任意“去指定地点教课/制作物品”的动作接口；新工作类型需要它自己的可验证执行器。

玩家聊天、原版日常改写、村民交谈均注入当前说话人的 `CURRENT JOB`。模型请求期间活动改变，过期回复会被丢弃。原版改写缓存也包含活动状态，避免恢复旧行为的台词。只注入当前说话人的工作详情，不提供其他参与者的私有目标和计划。

F9 对话页新增当前所选 NPC 的活动行，每半秒最多读取一次；长文本可悬停查看。报告原有实际提示词记录可追溯生成时的活动、目标、来源和失败原因。控制台 `aiworld_knowledge Penny` 也输出同一快照。新增界面标签和内置活动描述都有六种语言。

## 扩展与边界

- `AIWorld/ScheduleActivities` 对现有动作 ID 提供描述。内置值支持 `i18n:job.reading` 等翻译键；原有普通文本值继续有效。未知动作保留原始 ID，不随意推断。
- 新资产 `AIWorld/JobRules` 来自 `assets/job-rules.json`，可由 Content Patcher 修改。规则要求精确角色、地图、目标格和动作，再验证附近参与者；最多读 128 条规则，每条最多检查四名去重参与者、半径最多五格。
- `ActivityKey` 引用已有翻译，第三方规则可用 `Activity` 提供自有描述。描述只是有界文本，不能提供动作权限。地图或动作被其他模组改掉后，精确规则不再匹配，回退通用状态。
- 不把所有 NPC 的站立地点猜成职业工作。没有动作证据的柜台站立、未知模组工作显示到达/未知；详细工作标签需补充可靠数据或执行器。
- 不持久化一套影子状态；读档后从实际游戏、已恢复的约会和现存执行器重建。

## 验证范围

测试覆盖日程时间不能覆盖实际路线、移动→到达→动作、教室/学生/动作条件、跟随/出行/失败/等待/返回/剧情覆盖、未来约会不提前改当前任务、三类真实对话入口注入及活动变化后拒收旧回复。移动适配器合约测试验证观察状态不会推进路线，并识别接管和被替换的恢复执行。

离线测试和编译只能证明代码路径及接口；未启动真实存档、未调用付费模型，不代表已验证潘妮实际课堂时段或新增 F9 行的图形渲染。
